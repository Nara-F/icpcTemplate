# 内容编写与贡献流程

新增或修改算法内容时，先按算法类别归入已有章节和小节。单个新算法应作为所属章节中的普通小节，并沿用对应的检查入口；只有现有章节分类和检查域确实无法容纳的独立主题，才新建章节或测试入口，同时在 coverage 文档中说明归属依据。

内容、排版和导出分层维护：算法说明写在 `content/chapters/*.md`，不在正文硬编码分页、CSS 或导出细节；样式放在 `styles/`，文档框架放在 `templates/`，构建和格式转换放在 `scripts/`，源文件顺序与输出配置放在 `config/`。

## 小节模板

````markdown
## 编号 算法名称

**1. 它是做什么的**

说明适用范围、支持的操作、输入输出与限制；给出时间和空间复杂度。由朴素做法引出维护信息、不变量和复杂度依据，配一个可手算的小例。

**2. 变量在做什么**

解释真实字段和关键状态，区分点号、位置、离散编号与值域；字段较多时使用“名称 / 含义”表格。

**3. 函数在做什么**

列出主要接口的真实参数、返回值、副作用、索引约定、调用前提与重复调用行为。

**4. 怎么调用**

先说明依赖与调用顺序，再给模板和含具体输入、预期结果的最小调用片段。

```cpp
// 每个函数定义前写清参数、返回值或 void 副作用、下标和调用前提。
```

调用片段采用 `text` 围栏，避免将依赖上文的业务代码误当成独立模板；不能因此省略对真实 API 和预期结果的核对。

**5. 要改哪里**

结合模型识别，说明需求变化时应修改的状态、转移、比较条件或接口，以及哪些变化需要换算法。

**6. 自检**

给出手算结果、边界检查和由基础到组合应用的练习；适合时用独立暴力解对拍。

**7. 坑**

列出本算法具体的错误原因及修正方式，不以“注意边界”等通用提醒代替。

**8. 一句话原理**

用一句话概括该算法成立的核心理由。
````

第 04–09 章的算法小节采用上述八部分结构；在结构内保留零基础推导和必要的数学公式，不仅增加标签。学习路线与不含可提交模板的进阶指引可按主题组织，明确覆盖范围，不虚构接口或留空段落。标题编号和稳定锚点保持不变，锚点只在标题处定义一次。

每个函数、构造函数、辅助函数和 lambda 都要在定义前有具体契约注释，覆盖参数含义与范围、返回值；`void` 函数说明修改哪些结构、容器或调用方状态。依实现情况补充索引基准、输入合法性、失败/不可达值和重复调用行为。关键代码注释解释不变量、标记组合、边界处理等读代码不易直接看出的逻辑，不逐行复述语法。

## 检查与验收

代码块应能在文中声明的标准下独立编译，或明确列出并在检查时合并的代码依赖。行为检查应覆盖真实适用范围内有意义的边界；有随机输入风险时，可用小规模暴力解做差分。新增代码检查合入 `tests/check_foundations.py` 或 `tests/check_algorithms.py` 既有入口，只有新增主题确实属于不同测试域时才创建新的入口。纯文字调整不添加无意义测试；编译通过只说明语法有效，不等于算法逻辑正确。

发布前更新同层级章节编号与稳定锚点、关键词索引及 coverage 文档的普通条目。README 仅在项目结构或贡献/检查流程变化时同步，不为单个算法增加宣传段落。

完成修改后按影响范围运行 `make validate`、相应代码检查和 `make all`。检查 Markdown 标题与锚点、目录页码和 PDF 分页；渲染代表性页面核对代码、公式、表格、字体和页边界。算法正确性结论应由行为回归支持，不能只凭编译结果。

## 新内容检查清单

- [ ] 放入适当的既有章节；如新开章节或测试入口，记录无法归入现有分类/检查域的依据。
- [ ] 小节明确适用范围、支持操作、输入输出、边界和时空复杂度。
- [ ] 每个函数的参数、返回、副作用、索引、失败状态及必要的复用前提均与实现一致。
- [ ] 代码独立编译，依赖已声明；行为回归覆盖关键边界，必要时包含差分测试。
- [ ] 同步编号、稳定锚点、关键词索引和 coverage 普通条目；仅流程或结构变化时更新 README。
- [ ] 通过 `make validate`、对应测试入口和 `make all`，完成目录、分页及代表页视觉检查。
